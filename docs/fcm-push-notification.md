# FCM 푸시 알림 구현

## 왜 FCM인가?

브라우저 기본 Web Push API는 브라우저마다 동작이 달라 불안정합니다.
Firebase Cloud Messaging(FCM)은 구글이 만든 메시징 인프라로, 크로스 플랫폼에서 안정적으로 동작합니다.

---

## 알림이 오는 두 가지 경우

```
앱을 열고 있을 때  →  화면 안에 토스트 메시지로 표시
앱을 닫았을 때     →  스마트폰/PC 상단에 OS 알림으로 표시
```

두 경우를 처리하는 코드가 완전히 다릅니다. 각각 따로 구현했습니다.

---

## 1. 앱 닫혔을 때 — 서비스워커

서비스워커는 앱이 꺼져 있어도 백그라운드에서 돌아가는 별도 스크립트입니다.
FCM 메시지가 오면 서비스워커가 받아서 OS 알림을 띄웁니다.

**문제**: 서비스워커는 일반 `.js` 파일이라 환경변수(`process.env`)를 쓸 수 없습니다.
Firebase 설정 키를 파일에 직접 써야 하는데, 그러면 키가 그대로 노출됩니다.

**해결**: Next.js Route Handler를 서비스워커처럼 위장했습니다.

```
브라우저가 /firebase-messaging-sw.js 파일을 요청
        ↓
실제로는 Next.js 서버가 요청을 받음 (route.ts)
        ↓
서버가 환경변수 값을 읽어서 JS 코드 문자열에 끼워 넣음
        ↓
완성된 JS 코드를 응답으로 돌려줌
        ↓
브라우저는 이걸 서비스워커로 등록
```

키가 코드에 하드코딩되지 않고, 서버에서 런타임에 안전하게 주입됩니다.

---

## 2. 앱 열려있을 때 — 포그라운드 훅

앱이 열려 있으면 서비스워커가 아니라 React 훅이 메시지를 받습니다.

```ts
// 앱 전체에서 딱 한 번 등록
useForegroundMessaging()
```

메시지가 오면 두 가지를 동시에 합니다.

1. 앱 안에 토스트 메시지 표시
2. OS 알림도 같이 표시 (실패하면 브라우저 기본 Notification API로 대체)

---

## 3. 전역으로 등록하는 방법

훅을 루트 레이아웃에서 한 번만 호출하면, 어떤 페이지에 있어도 알림을 받을 수 있습니다.

```
앱 전체 (layout.tsx)
  └─ FcmMessagingProvider  ← 여기서 훅 한 번 호출
        └─ 모든 페이지
```

`FcmMessagingProvider` 자체는 3줄짜리 컴포넌트입니다. 훅을 호출하고 자식을 그대로 렌더링하는 역할만 합니다.

---

## 4. 알림 켜기 / 끄기

알림 페이지에서 토글을 누르면 아래 순서로 동작합니다.

**켜기**
```
토글 ON
  → 브라우저 알림 권한 팝업 표시
  → 허용 시 FCM 토큰 발급 (기기 고유 식별자)
  → 토큰을 서버 DB에 저장
  → 이후 서버가 이 토큰으로 알림 발송 가능
```

**끄기**
```
토글 OFF
  → 서버 DB에서 토큰 삭제
  → 더 이상 이 기기로 알림 안 옴
```

---

## 5. 서버가 알림을 보내는 시점

루틴에 알림 시간을 설정하면, 서버가 매 분마다 해당 시각의 루틴을 조회하고 FCM으로 알림을 발송합니다.

```
매 분 체크
  → 지금 이 시각에 알림 설정된 루틴 있나?
  → 있으면 해당 유저의 FCM 토큰 조회
  → Firebase로 푸시 발송
  → 유저 기기에 "오늘의 루틴을 실천할 시간이에요! 💪" 표시
```

---

## 정리

| 상황 | 처리 방식 |
|------|-----------|
| 앱 열려 있음 | React 훅(`onMessage`) → 토스트 + OS 알림 |
| 앱 닫혀 있음 | 서비스워커(`onBackgroundMessage`) → OS 알림 |
| 알림 켜기 | FCM 토큰 발급 → DB 저장 |
| 알림 끄기 | DB에서 토큰 삭제 |
| 루틴 알림 | 서버가 매 분 체크 → FCM 발송 |
| 키 보안 | Route Handler로 env 값 런타임 주입 |
